How to become an Algorithmacy engineer.

You open a pull request. It adds your photo and details to the Studio page, and it shows that you can do the work. If it is approved, two things happen: the page is updated, and the email in the pull request is added to the engineer list. Then you can sign in.

Opening a pull request does not assign you a client. It is not a job offer, and it does not set a salary. The client pays the studio. The engineer is the named person on an account.

Open the repository Engineers on the Studio page

The work.

What the name means.

An engineer learns an owner-run office and sets up agents for its chores: intake, chasing documents, reminders, and follow-ups. After a run, the engineer posts one plain report the office can read. A person at the firm signs off before a new kind of message goes out, and can stop any of it.

The engineer does not do the office’s professional work. In a law firm, a lawyer does the law. The agents do the chores. Client files stay in the office’s own systems.

The pull request.

One request, to main.

  1. 1

    Fork the repository. rogerSuperBuilderAlpha/algorithmacy-conference.

  2. 2

    Add a square photo at images/speakers/your-name.jpg. Use your name in lowercase, with hyphens. Roger’s file is images/speakers/roger-hunt.jpg.

  3. 3

    Add yourself on the Studio page. In studio/index.html, find “The engineer.” Copy the person block that is already there and put yours after it. Change the photo path, your name, two sentences a client could read, and your LinkedIn link.

  4. 4

    Put the rest in the pull request description, not in the page. The sign-in email, the chore, and the sample report stay off the public page.

  5. 5

    Open the pull request to main. Title it “Add your name to the Studio engineers.”

What to demonstrate.

This is what approval reads.

The photo and the two sentences show who you are. The pull request description has to show the work. All four of these have to be there.

  1. Email

    The address you will use to sign in. Write it in the pull request description. A GitHub noreply address is not enough. This is the address that gets added to the engineer list if you are approved. It is not printed on the Studio page. Anyone who can see the pull request can see this address. Sign-in also asks for a code from an authenticator app. The address alone does not open the portal.

  2. Chore

    One office chore, and the agent that does it. Intake, chasing a document, a reminder, or a follow-up. Say what the agent does, in language a person at the firm can read. Say what it does not do.

  3. Sign-off

    Who says yes before a new kind of message goes out. Name the role, not a client. A person at the firm signs off. The agent does not send a new kind of message on its own.

  4. Report

    One sample report. One or two sentences, the way you would say it to the office after a run. An example of the shape, not a real client: “Chase collected the missing tax return. The engagement letter is still out.” No transcript. No document. No file path.

Approval.

Two steps, both required.

If the pull request shows those four things, and the page block matches the engineers already there, it can be merged. Merging updates the Studio page.

The email from the pull request description is then added to the engineer list. That is a separate step from the merge. When it is done, sign in at the portal with that same email. The first sign-in sets up an authenticator. After that, the portal asks for a code from it. Use the Engineer view.

A pull request that is closed without a merge does not add you to the page or to the engineer list. You can open another one.

What is not enough.

A photo and a bio, with no chore, no sign-off, and no sample report. An email that is only a GitHub noreply address. A client name, a client file, a key, or a transcript in the pull request. A description of an agent that sends a new kind of message with no person signing off.

Questions about a pull request go on the pull request. Other questions go to topanga@algorithmacy.org.
